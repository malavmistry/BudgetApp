# Change Management

## Documentation change process

1. Identify the authoritative document for the rule.
2. Update that document first.
3. Update dependent agent or checklist documents.
4. Review for contradictions and duplicates.
5. Record an ADR if the change is architectural.

## Conflict resolution process

1. Detect the conflict.
2. Identify the authoritative source.
3. Do not silently choose an interpretation if the difference is material.
4. Escalate architecture conflicts.
5. Update the documentation set once the decision is made.

## Docs-system modification rule

Changes to the docs system itself are engineering changes and MUST preserve discoverability, single-source ownership, and non-contradictory rules.
